# SNAKISH v1 Implementation Plan

> **For Hermes:** Execute this plan through the local Codex CLI in small, bounded tasks. Hermes owns architecture, diff review, verification, GitHub operations, and readiness reporting. Do not reuse or inspect the previous Snake implementation.

**Goal:** Build SNAKISH from scratch as a polished, accessibility-first neon/grid Snake game for desktop and mobile browsers.

**Architecture:** A static, client-only TypeScript application built with Vite. Deterministic game rules live in a pure engine independent of rendering; a Canvas renderer provides the neon arcade presentation; DOM-based controls and dialogs provide accessible interaction. Scores and user preferences remain local to the browser. Deployment uses GitHub Pages with the custom hostname `snake.trauthwein-solutions.com`.

**Tech Stack:** TypeScript, Vite, HTML Canvas, CSS, Web Audio API, Vitest, Playwright, ESLint, Prettier, GitHub Actions, GitHub Pages.

---

## 1. Confirmed product decisions

- **Name:** SNAKISH
- **Visual direction:** polished neon/grid arcade
- **Scope:** classic Snake with excellent game feel; no power-ups, hazards, accounts, online leaderboard, or progression system in v1
- **Platforms:** desktop and mobile web browsers
- **Controls:** keyboard, swipe gestures, and visible touch controls
- **Audio:** music and sound effects with separate mute controls
- **Walls:** lethal
- **Difficulty:** speed increases gradually during a run
- **Persistence:** save only the best score locally on the device
- **Accessibility:** accessibility-first in v1
- **Delivery rule:** start from scratch; do not recover or copy the earlier implementation

## 2. v1 player experience

### Start screen

- SNAKISH wordmark and short “enter the grid” style subtitle
- Primary **Play** button
- Best score
- Keyboard/touch instructions that adapt to input capability
- Separate music and sound-effect controls
- Accessible settings for reduced motion and high contrast

### Gameplay

- Responsive square arena centered within the available viewport
- Snake begins in a safe, deterministic position and direction
- Food never spawns on the snake
- Eating food increases score and snake length
- Speed increases in capped steps so late-game play remains controllable
- Collision with a wall or the snake ends the run
- Direction reversal into the snake is rejected
- Pause/resume via button, `P`, or `Escape`
- Game automatically pauses when the document becomes hidden or loses focus
- Touch gestures use an intentional movement threshold to avoid accidental turns
- Visible directional controls remain large enough for touch use

### Game-over screen

- Final score
- New-best-score treatment when applicable
- **Play again** button
- Return to title/settings option
- No forced sharing, account creation, or network request

## 3. Accessibility acceptance criteria

- All game setup, pause, restart, audio, and settings actions are keyboard operable
- Focus is visible and moves predictably when dialogs open or close
- Touch targets are at least 44×44 CSS pixels
- Current score, best score, pause state, and game-over result have text equivalents
- Important state changes use a restrained `aria-live` region; movement ticks are not announced
- High-contrast mode does not depend on neon color alone
- Reduced-motion mode removes flashes, camera shake, and nonessential transitions
- The game remains understandable with audio muted
- Audio does not autoplay before the first user interaction
- Canvas has a meaningful accessible label and nearby text instructions
- Layout works at 320 CSS pixels wide and at 200% browser zoom
- Desktop and mobile browsers avoid page scrolling while an intentional swipe/control input is used over the game area

## 7. Risks and mitigations

- **Mobile browser viewport/input quirks:** use visual viewport-safe CSS, intentional gesture handling, and real mobile viewport tests.
- **Canvas accessibility:** keep all controls and state in semantic DOM; Canvas is presentation, not the only information channel.
- **Audio autoplay restrictions:** create/resume the audio context only following direct user interaction.
- **Nondeterministic game tests:** inject a seeded random source and control the simulation clock.
- **High-DPI blur:** size Canvas backing pixels using device pixel ratio while drawing in CSS coordinates.
- **GitHub Pages custom-domain TLS:** verify DNS and Pages certificate readiness separately before changing live DNS.
- **Scope growth:** keep v1 to excellent classic Snake; defer online scores, user accounts, skins, power-ups, and multiple modes.
